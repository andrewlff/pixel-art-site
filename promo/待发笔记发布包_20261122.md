## 第 1 篇 · D8 教程干货

**标题**（19 字）：像素图在Godot里发糊？4项设置搞定

**正文**（直接复制）：

```
导入素材进 Godot 4 之后，像素图变成一片柔光糊图——多数不是美术问题，是导入设置默认给的是 3D 友好的参数。
只改 4 项，1 分钟出效果：
① Filter Mode：Linear → Nearest（关掉双线性插值，这是糊的主因）
② Mipmaps：关掉（小尺寸像素图不需要，开着必糊）
③ Compression：→ Lossless（VRAM 压缩会让色块掉色、边缘抖动）
④ 项目设置里开 2D 变换取整（渲染像素对齐，解决半像素位移导致的抖动）
改完再进场景，同样的图从糊变成锐利色块，缩放也不再糊边。同一套参数在 Unity 里对应 Filter Mode = Point、Compression = None。
这套「立绘→像素化→图集→GIF」的批处理我开源成了三个仓库：pixel-art-action-frames（角色动作帧与图集）、godot-pixel-batch-tool（Godot 编辑器内批量）、unity-pixel-batch-tool（Unity 编辑器窗口批量）。
仓库地址在评论区置顶/主页，喜欢请收藏+关注，⭐star 支持开源。
```

## 第 2 篇 · D10 教程干货

**标题**（16 字）：图集切错12px，动作全变成鬼影

**正文**（直接复制）：

```
角色动作帧画完了，扔进引擎一播，人物像在抖、在拖影——大概率不是帧画坏了，是图集切错了。
我这份像素动作图集是一整张图：3072×504，6 列 × 1 行，每格 512×504，6 帧共用一个透明通道，每帧停 120 毫秒、循环播放。切帧不需要看画面猜，仓库里的 attack_sheet.json 已经写清楚 6 个数：
cols = 6（横向 6 格）
rows = 1（纵向 1 行）
cell_w = 512（每格宽，直接决定切的位置）
cell_h = 504（每格高）
frame_ms = 120（每帧 120 毫秒）
loop / alpha = true（循环、带透明通道）
按这 6 个数等分切，6 帧干净利落。最常踩的坑是把 cell_w 写小一点（比如 500）：偏移量 = (512−500) × 帧序号，到第 6 帧已经偏 60 px，每帧都会带进一点相邻帧的边缘，播起来就是鬼影和抖动。我图里把两种切法并排放了，能直接看出第二排每格右边多出一条。
引擎侧对应设置：Godot 用 AtlasTexture 的 region_rect 按 rect 取帧；Unity 是 Sprite Mode = Multiple、Grid 填 512×504，别用 Automatic。
这套「立绘→像素化→图集→GIF」的批处理我开源成了三个仓库：pixel-art-action-frames（角色动作帧与图集 + JSON 清单）、godot-pixel-batch-tool（Godot 编辑器内批量）、unity-pixel-batch-tool（Unity 编辑器窗口批量）。
```

## 第 4 篇 · D12 教程类

**标题**（14 字）：GIF后几帧露底，3步修干净

**正文**（直接复制）：

```
GIF 导出来，前两帧还好，后几帧底下突然冒出一片浅绿，甚至一块纯黑——这不是播放器的问题，是文件里底色没抠干净。
我把手上 8 个角色、48 帧逐个量了一遍：
·修前平均 8.25% 的不透明像素是浅绿残底，最坏一帧 49.6%
·按「认角色 → 清边界底色 → 逐帧回读」三步修完，平均降到 0.36%，最坏一帧 0.4%
三步具体怎么做（第二张图）：
1. 先把角色认出来：取「非浅色」像素里最大的连通块当轮廓；被它包住的浅色洞（衣服、高光）要补回来，否则会挖空
2. 再清和边界连通的底色：浅绿/浅蓝按低饱和、高亮度判定，纯黑底板单独一条规则；只清够得到画布边界的，角色内部的绿不动
3. 最后逐帧回读验一遍：读回文件量残留率，别只在内存里看数组
三个坑（第三张图）：
·四角是 (0,0,0,0)，拿边框中位色估底会估出黑色，越修越错
·GIF 只有第 1 帧带透明标记时，后几帧会把透明索引画成黑色
·种子落在零散特效像素上，会把角色只认出一小块，整帧被删
代码就是我跑的这一份，8 个角色的修复版 GIF 也在仓库里：
pixel-art-action-frames —— 拆帧、图集、GIF、JSON
godot-pixel-batch-tool / unity-pixel-batch-tool —— 引擎侧批量处理
```
